1. File Organization
================================================================================

The CORSIKA 7.8010 source-code system is unified in the following files:

1.1 Main source files

  src/corsika.F        — main program file (84803 lines), containing:
    • All Fortran code from program entry to exit
    • Implementations of all physics processes
    • #if/#else/#endif conditional-compilation directives controlling various options
    • Steering-card documentation and output-format documentation in inline-comment form

  src/corsika.h         — header file (5362 lines), containing:
    • All COMMON block definitions
    • Data dimension constants (MAXLEN, MAXSTK, MAXBUF, etc.)
    • Particle array index constants
    • STACKFINC include block (particle-stack dimension definitions)

1.2 External model files (compiled separately and linked)

  src/sibyll2.3e.f         SIBYLL 2.3e hadronic model
  src/sibyll2.3e-star.f    SIBYLL-star variant
  src/qgsjet01d.f          QGSJET01d model
  src/qgsjet-II-04.f       QGSJET-II-04 model
  src/qgsjet-III.f         QGSJET-III model
  src/gheisha_2002d.f      GHEISHA low-energy hadronic model
  src/venus.f              VENUS model
  src/fluka_interface.f    FLUKA interface
  src/elfield.c            electric-field option C code

  Individual hadronic model directories (urqmd/, epos/, herwig/, dpmjet/, nexus/, pythia/):
  unpacked and linked at compile time.

1.3 Header files and configuration files

  include/config.h.in   →  ./configure → config.h

2. Preprocessor Macro System and Options
================================================================================

2.1 How macros are defined

  CORSIKA uses the C preprocessor (#if / #else / #endif) to implement conditional compilation:
  - Early versions: passed to the Fortran compiler via -D__OPTION__
  - Modern versions: macros defined via config.h (generated by the ./coconut configuration)

  There are about 3750 #if directives in the code, trimming the code according to the options activated at compile time.

2.2 Option categories

  (A) Geometry and coordinate system
    Macro          Function
    __CURVED__    Curved atmosphere (spherical Earth, supports θ>70°)
    __SLANT__     Slant-depth longitudinal distribution (SLANT option)
    __UPWARD__    Upward particles (θ>90°)
    __INCLINED__  Inclined observation plane (COAST interface)
    __VIEWCONE__  View cone angle selection

  (B) Hadronic models
    __SIBYLL__    SIBYLL 2.3
    __QGSJET__    QGSJET-II/QGSJET01d
    __EPOS__      EPOS LHC
    __DPMJET__    DPMJETIII
    __NEXUS__     neXus
    __VENUS__     VENUS
    __HDPM__      HDPM (default built-in)
    __FLUKA__     FLUKA (low energy)
    __GHEISHA__   GHEISHA (low energy, built-in)
    __URQMD__     UrQMD (low energy)

  (C) Electromagnetic physics
    __CERENKOV__  Cherenkov photons
    __LPM__       LPM effect
    __EFIELD__    Electric field

  (D) Data processing
    __THIN__      Thinning
    __MULTITHIN__ Multi-thinning
    __THINMAX__   Maximum-weight thinning
    __COMPACT__   Compressed output
    __EHISTORY__  Particle history (parent/grandparent particles)
    __MUADDIOUT__ Muon additional output
    __MUPROD__    Muon production information
    __NEUTRINO__  Neutrino tracking

  (E) Detectors
    __AUGERHIST__ Auger histogram
    __AUGERHIT__  Auger hit
    __ICECUBE1__/__ICECUBE2__  IceCube
    __IACT__      Cherenkov telescope
    __COAST__     COAST interface
    __COASTUSERLIB__  User library

  (F) Special modes
    __CONEX__     Hybrid cascade-equation simulation
    __PRESHOWER__ Preshower
    __NUPRIM__    Primary neutrino
    __STACKIN__   Stack input (external secondary particles)
    __PARALLEL__/__PARALLELIB__  MPI parallel
    __INTTEST__   Interaction test
    __TRAJECT__   Source trajectory tracking
    __CHARM__/__TAULEP__  Charm/τ lepton
    __RIGIDITY__  Geomagnetic cutoff
    __DYNSTACK__  Dynamic stack (runtime allocation)
    __ATMEXT__    External atmosphere (MODTRAN)
    __NRREXT__    Extended run number

2.3 Option combination constraints

  Important mutual exclusions/dependencies:
  - CURVED + CONEX: mutually exclusive (CONEX internally uses part of the CURVED code)
  - CURVED + NKG: NKG automatically disabled (spherical geometry not applicable)
  - THIN + THINMAX: THINMAX must be selected on top of THIN
  - SLANT + CONEX: mutually exclusive
  - INCLINED + COAST: required
  - ROOTOUT + COREAS/COASTUSERLIB/INCLINED: mutually exclusive

2.4 NON_OPT group

  A group of macros for encoding the "no option" mode (__NON_OPT0__ through __NON_OPT4__),
  enabled in standard modes such as non-CURVED/non-SLANT/non-CERENKOV. Contains:
  - THICK function
  - HEIGH function
  - BOX2 / BOX3
  - PRANGE
  - UPDATE / OUTPT1
  - MUTRAC

3. Overall Program Flow
================================================================================

3.1 Entry points (polymorphic design)

  PROGRAM AAMAIN (line 1337)
    ↓ (called sequentially)
  SUBROUTINE CORSIKAMAIN (line 1382)    ← core main routine
    ↑
  SUBROUTINE CORSIKA (line 1315, only __PARALLELIB__)
    ── serves as an MPI-callable library interface, receiving parameters such as LPRIM

  At the end of the file there is also a spare PROGRAM AAMAIN (line 84794), used when HAVE_CONFIG_H is not defined.

3.2 Phase breakdown

  CORSIKAMAIN execution is divided into 4 phases:

  ┌─────────────────────────────────────────────────────┐
  │ Phase 1: Initialization (lines 1382-1920)           │
  │   • Call DATAC to read all steering cards (→ INPRM) │
  │   • Open files (FILOPN)                             │
  │   • Write run header block (RUNH)                   │
  │   • Initialize random numbers (RMMAQD)              │
  │   • Set atmosphere model parameters                 │
  │   • Print run parameters (about 200 lines to .lst)  │
  ├─────────────────────────────────────────────────────┤
  │ Phase 2: Event loop (lines 1923-3174)               │
  │   DO ISHW = 1, NSHOW                                │
  │     ① ISTACK: clear the particle stack              │
  │     ② Sample primary-particle energy/angle/first-interaction point │
  │     ③ BOX2: first-interaction position determination │
  │     ④ Dispatch by particle type (EM/μ/hadron/neutrino) │
  │     ⑤ ENTRY RUNSHOWER: process the cascade          │
  │     ⑥ ENTRY FINISHSHOWER: end-of-event statistics   │
  │   END DO                                            │
  ├─────────────────────────────────────────────────────┤
  │ Phase 3: Run end (lines 3175-3183)                  │
  │   • ENTRY FINISHRUN: run summary                    │
  │   • Write RUNE block                                │
  ├─────────────────────────────────────────────────────┤
  │ Phase 4: Wrap-up (after CORSIKAMAIN returns)        │
  │   • Close files                                     │
  │   • Output CPU time statistics                      │
  └─────────────────────────────────────────────────────┘

3.3 Detailed event loop flow

  ┌────────────────────────────────────────────────────────────┐
  │ 1. Sample primary-particle parameters                      │
  │    • PRMPAR(0): particle type (fixed or random)            │
  │    • PRMPAR(1): total energy (E⁻ᵞ spectrum or fixed)       │
  │    • THETAP: apparent zenith angle (sinθ·cosθ distribution) │
  │    • PHIP: azimuth angle (uniform)                         │
  │    • First-interaction point: FIXHEI/random (exponential decay) │
  │    ┌─ CURVED mode ──────────────────────────┐              │
  │    │ • COOINC: compute spherical-geometry initial coordinates │
  │    │   coordinates → detector frame, core at (0,0,0)       │
  │    │ • Generate secondary-particle energy/momentum/start position │
  │    └─────────────────────────────────────────┘              │
  │                                                            │
  │ 2. Dispatch particle type (lines 3017-3109)                │
  │    γ / e⁺/e⁻ → EM → EGS4 or NKG                            │
  │    μ⁺/μ⁻     → MUPINI → MUTRAC                             │
  │    hadrons    → NUCINT (hadronic interaction)              │
  │    π⁰/K⁰     → decay                                       │
  │    neutrinos  → neutrino tracking                          │
  │                                                            │
  │ 3. Particle stack loop (ENTRY RUNSHOWER, line 3188)        │
  │    DO WHILE (stack not empty)                              │
  │      CALL FSTACK → CURPAR(0:39)                            │

  │      - EM: CALL BOX2 → EGS4                                │
  │      - reaching the observation level: CALL UPDATE → OUTPT1 │
  │    END DO                                                  │
  │                                                            │
  │ 4. Event end (ENTRY FINISHSHOWER, line 3899)               │
  │    • Event statistics                                      │
  │    • NKG lateral distribution (if any)                     │
  │    • Write EVTE block                                      │
  └────────────────────────────────────────────────────────────┘

  9       pz momentum z component (GeV/c, positive downward)

  11-19   (reserved)
  20      Kinetic energy (GeV)
  21      Total energy recorded again
  22      Particle number
  23      Observation-level number
  24      Hadronic generation

5. Particle Stack System (Stack)
================================================================================

The particle stack is CORSIKA's core work queue, using a "last-in, first-out" (LIFO) strategy.

5.1 Data structure

  STACKI(0:MAXLEN, 0:MAXSTK)  — main stack
  Each particle occupies MAXLEN+1 = 42 real-array elements (1 word for internal counting).
  STACKI(0, k) is unused; STACKI(1:41, k) corresponds to CURPAR(0:39) + flag bits.

5.2 Stack operations

  ISTACK (line 20068):
    Initialize the main stack: set MSTACKP to 0, clear counters.

  FSTACK (line 17161):
    Pop a particle from the stack:
      MSTACKP = MSTACKP - MAXLEN - 1
      CURPAR(J) = STACKI(MSTACKP+J+1, 0)
    If the stack is empty (MSTACKP ≤ 0), try reading from disk (NOUREC).
    If there is no more data on disk, IRET1 = 1 indicates the stack is empty.

  Push particle (inline, not a separate subroutine):
    In processes such as NUCINT/DECAY, build SECPAR, then:
      MSTACKP = MSTACKP + MAXLEN + 1
      STACKI(MSTACKP+J+1, 0) = SECPAR(J)
    When the stack is full, write to a direct-access disk file (unit LSTCK).

  TSTEND (line 35782):
    Transfer STACKINT (the intermediate stack of one nuclear reaction) to the main stack STACKI.
    THIN thinning is applied here (if enabled).

5.3 Stack overflow handling

  When MSTACKP >= MAXSTK * (MAXLEN+1):
    • Write the current stack contents to the direct-access file (LSTCK)
    • Reset MSTACKP = 0
    • NOUREC records the number of blocks written
  The reverse operation is performed when reading back.

5.4 Secondary stack (parallel mode)

  STACKJ — a second stack, used for __PARALLEL__ mode or for the external
  particle input (STACKIN) of __COASTUSERLIB__.

  JSTACK (line 20116): initialize the secondary stack
  FSTACKJO (line 17599): push onto the secondary stack

6. Steering Card Reading and Parameter Initialization
================================================================================

6.1 DATAC subroutine (line 10812)

  Reads all input steering cards and sets global variables:
  • Reads line by line from unit MONIIN (default 5, standard input)
  • Recognizes keywords (first 6 characters), jumps to the corresponding processing code
  • Handles basic types: I (integer), F (float), L (logical), A (character)
  • Case-insensitive (except for special character parameters such as EPOPAR/NEXPAR/DIRECT)
  • Comment lines: first character c/C + space, or *

6.2 INPRM subroutine (line 18124)

  After DATAC has read all cards, INPRM performs:
  • Read primary-flux weights from the PAPINI file (used for spectrum sampling)
  • Validation of default values
  • Computation of derived parameters (e.g. atmosphere layer THICKL)
  • Initialization of physical constants (the C() array)

6.3 Internal processing paths of common cards

  Card           DATAC handling
  ──────────────────────────────────
  RUNNR          → NRRUN (integer)
  EVTNR          → ISHOWNO start
  SEED           → ISEED(3, k) settings
  NSHOW          → NSHOW
  PRMPAR         → PRMPAR(0)
  ERANGE         → LLIMIT, ULIMIT
  ESLOPE         → PSLOPE
  THETAP         → THETPR(1:2) (degrees→radians conversion)
  PHIP           → PHIPR(1:2)
  OBSLEV         → OBSLEV(1:NOSBLV)
  ECUTS          → ELCUT(1:4)
  SIBYLL/SIBSIG  → FSIBYL/FSIBSG flags
  ELMFLG         → FNKG/FEGS
  THIN           → EFRCTHN/WMAX/RMAX
  CURVOUT        → FCURVOUT
  MAGNET         → BX/BZ
  ATMOD          → MODATM
  EXIT           → end of reading

7. Atmosphere Model Subsystem
================================================================================

See atmosphere_model_summary.txt for details (a separate document in this directory).

7.1 Core functions

  THICK(H)  (line ~17913, __NON_OPT__ group):
    Input: height H (cm)
    Output: vertical atmospheric depth (g/cm²)
    Formula:
      Layers 1-4: t(h) = A(i) + B(i) * exp(-h / C(i))
      Layer 5:    t(h) = A(5) - h / C(5)

  HEIGH(T)  (line 17906):
    Input: vertical atmospheric depth (g/cm²)
    Output: height H (cm)
    Inverse function of THICK, solved analytically per layer.

  THICKC(OBSLEV, COSIN)  (line ~34128, __CURVED__ group):
    Input: observation height, local zenith-angle cosine
    Output: curved slant depth (g/cm²)
    Iteratively solves the slant depth in a spherical atmosphere, using the sliding-plane approximation.

7.2 Atmosphere model data

  42 built-in models (MODATM=0~41):
  - MODATM=1: US Standard Atmosphere (Linsley) [default]
  - MODATM=2~8: Central European monthly atmospheres
  - MODATM=11~16: South Pole (MSIS-90-E)
  - MODATM=17: US Standard Atmosphere (Keilhauer)
  - MODATM=18~29: Malargüe (Auger monthly)
  - MODATM=30~41: South Pole IceTop monthly
  - MODATM=0/10: user-defined (ATMA/B/C/ATMLAY)

  5 layer boundaries (HLAY): 4, 10, 40, 100 km, Earth radius (1e7 cm ≈ Earth center)
  Top-layer linear approximation: layer 5 down to the Earth center.
  Sea-level depth: ~1036 g/cm² (US Standard)

7.3 Key atmosphere-related subroutines

  RFILEATM (line 30092): read an external atmosphere profile from the ATMFILE file
  ATABSO (line 76338): atmospheric absorption (Cherenkov option)
  External atmosphere A(i)/B(i)/C(i) → internal code arrays ATMA/ATMB/ATMC

8. Coordinate System
================================================================================

8.1 Standard Cartesian system

  Origin: sea level (OBSLEV=0) or the first observation level
  x axis: magnetic north direction
  y axis: west direction
  z axis: vertically upward
  Zenith angle θ: relative to the -z axis (straight down is 0°)
  Azimuth angle φ: counterclockwise from magnetic north (0° along +x, 90° along +y)
  Momentum pz: positive downward (convention along the particle propagation direction)

8.2 CURVED mode sliding plane

  In __CURVED__, Earth radius C(1)=637131500 cm:
  - Particles are continuously tracked in the curved atmosphere
  - The coordinate-system origin is located at the detector position at sea level
  - After each step, the local coordinate system is rotated so the z axis points toward the Earth's center again
  - COOINC (line 9445): compute the apparent-angle→local-angle transformation
  - THICKC (line ~34128): slant-depth iteration for the curved atmosphere
  - NRANGC (line 25305): curved tracking of neutral particles
  - PRANGC (line 28849): curved tracking of charged particles (including the magnetic field)
  - CORRXY: spherical→planar projection correction (called in OUTPT1)
  - Output coordinates OUTPAR(5,6): relative to the detector (horizontal-plane projection)

8.3 INCLINED inclined observation plane

  - An alternative option independent of CURVED mode
  - Defines an inclined plane perpendicular to or containing the shower axis
  - Output in the inclined-plane coordinate system, with (X=0,Y=0) at the intersection of the shower axis and the plane

9. Main Loop and Particle Scheduling
================================================================================

9.1 Particle classification and scheduling (lines 3017-3109)

  In the event loop, after its first interaction the primary particle enters the particle stack, the RUNSHOWER entry
  point (line 3188) opens the main processing loop. Per-particle classification and scheduling happen at lines 3320-3860:

  ┌─ Dispatch by CURPAR(0) particle type ───────────────────────┐
  │                                                     │
  │  γ, e⁺, e⁻ ──────────→ EM processing                │
  │    • EGS4: EM subroutine → exact simulation of e/γ cascades │
  │    • NKG (non-CURVED mode): analytical formula calculation │
  │    └─→ secondaries pushed onto the stack             │
  │                                                     │
  │  μ⁺, μ⁻ ────────────→ MUTRAC subroutine             │
  │    • Ionization energy loss (CDEDXM)                │
  │    • Multiple scattering (Molière/Gauss)            │
  │    • Bremsstrahlung / pair production / nuclear interaction │
  │    • Decay (MUDECY)                                 │
  │    • Propagation to the observation level or energy exhaustion │
  │    └─→ arrivals → UPDATE → FSTACKO output           │
  │                                                     │
  │  hadrons ────────────→ NUCINT subroutine            │
  │    • Select high-/low-energy model                  │
  │    • Nuclear interaction → secondary particles      │
  │    • Unstable hadron decay (KDECAY, PI0DEC, etc.)   │
  │    └─→ secondaries pushed onto intermediate stack → TSTEND → main stack │
  │                                                     │
  │  neutrinos/τ ────────→ neutrino/τ propagation       │
  │                                                     │
  │  π⁰ → PI0DEC → γe cascade                           │
  │  K⁰S/K⁰L → KDECAY                                   │
  │  nuclear fragments → fragmentation (NFRAGM)         │
  │                                                     │
  └─────────────────────────────────────────────────────┘

9.2 Stack loop termination conditions

  The stack loop continues until any of the following conditions is met:
  • FSTACK returns IRET1=1 (stack empty and no data on disk)
  • The particle count exceeds MAXPRT and the elapsed time exceeds expectations
  • The maximum stack-depth limit is reached

10. Physics Process Implementation
================================================================================

10.1 Hadronic interactions

  NUCINT (line 25469) — unified entry point:
    Dispatches according to particle type and energy:

    High-energy region (Elab > HILOW, default 80 GeV):
      Handled by the model selected at compile time:
        #if __QGSJET__  → QGSLNK (line 69882)
        #if __SIBYLL__  → SIBLNK (line 71686)
        #if __EPOS__    → EPOLNK (EPOS directory)
        #if __DPMJET__  → DPMJLK (line 59542)
        #if __VENUS__   → VENLNK (line 74810)
        #if __NEXUS__   → NEXLNK (line 66418)
        #else           → HDPM   (line 61815, built-in)

    Low-energy region (Elab ≤ HILOW):
      #if __FLUKA__     → FLUSTR (line ~54200, FLUKA interface)
      #if __URQMD__     → URQMD (line 68371)
      #else             → GHEISHA (built-in)

    Nuclear fragmentation (NFRAGM):
      #if __SIBYLL__/__QGSJET__: the model itself provides fragmentation
      #else: HDPM fragmentation model

    After each interaction:
      Secondary particles are filled into STACKINT, then TSTEND transfers them to the main stack.

10.2 Electromagnetic interactions

  NKG (non-CURVED mode, lines ~3900-4860 in FINISHSHOWER):
    Uses the Greisen approximation formula to compute the e⁺/e⁻ lateral and longitudinal distributions.
    Computed at the end of the event; particles are not pushed onto the stack.

  EGS4 (line 15590, EM subroutine):
    Full simulation of e⁺/e⁻/γ electromagnetic cascades:
    • Bremsstrahlung
    • Pair production
    • Compton scattering
    • Photoelectric effect
    • Møller scattering (Bhabha/Møller)
    Secondary particles are managed through the EGS4 internal stack.
    The step size is controlled by STEPFC.

10.3 Muon physics

  All implemented inside corsika.F (no external libraries):

  MUPINI (line 23859):
    Muon-pair initialization (γ → μ⁺μ⁻ photoproduction process)

  MUPRPR (line 24230):
    Muon propagation parameter preparation

  MUTRAC (line 24621):
    Core muon propagation routine:
    • Ionization energy loss: dE/dX (CDEDXM)
    • Multiple scattering: (MUMULT selects Molière/Gauss)
    • Bremsstrahlung: MUBREM (line 22567), DBRELM (line 12951)
    • Pair production: CPRSGM (line 10515)
    • Nuclear interaction: MUNUCL (line 23329), CNUSGM (line 9280)
    • Decay: MUDECY (line 22938)
    • Coulomb scattering: MUCOUL (line 22874)
    Reaching the observation level → UPDATE (compensating transport to the exact observation level)

  UPDATE (line ~17850-17900, NON_OPT group):
    Transports the particle from its current position to the exact observation level:
      OUTPAR(5) = X + SN1 * U10 + ...
      OUTPAR(6) = Y + SN1 * V10 + ...
    • SN1 = (OBSLEV(1) - Z) / CZ (projection along the particle direction)
    • Energy-loss correction (dE/dX)
    • CURVED mode: compensation using the sliding plane

10.4 Decay

  DECAY1 (line 13095):
    Two-body decay (π⁺→μ⁺ν, K⁺→μ⁺ν, etc.)
    Isotropic parent-particle frame → lab-frame transformation

  DECAY2 (line 13345):
    Multi-body decay (K⁺→π⁺π⁰, etc.)
    Uses phase-space weighting

  DECAY6 (line 13560):

11. Output System (DAT File)
================================================================================

11.1 File structure

  Fortran unformatted sequential file, default block length 22932 bytes (5733 words × 4 bytes):
  each block = 21 sub-blocks × 273 words.

  ┌─────────┬──────────┬──────────┬──────┬──────────┬─────────┐
  │ RUNH    │ EVTH #1  │ DATA ... │ ...  │ EVTE #1  │ EVTH #2 │
  │ (run header) │ (event header 1) │ particle data blocks │      │ (event trailer 1) │ (event header 2)│
  └─────────┴──────────┴──────────┴──────┴──────────┴─────────┘
  ┌─────────┐
  │ RUNE    │
  │ (run trailer) │
  └─────────┘

  Each write packs the floating-point arrays into 4 bytes via the C routine tobuf.c (line 84440+).

11.2 Key output subroutines

  FSTACKO (line 17544):
    Writes particles that reached the observation level (OUTPAR) into the particle-data sub-blocks of the DAT file.

  OUTPT1 (line 26485):
    Pre-output processing:
    • CURVED mode: call CORRXY to correct the spherical projection
    • Non-CURVED mode: subtract the XOFF/YOFF core offset

  OUTEND (line 26311):
    At event end, writes the EVTE (event trailer) sub-block, containing the NKG lateral distribution.

  OUTPT3 (line 27447):
    Muon additional information (parent particles) output.

11.3 Output under thinning

  With THIN enabled, the block length increases to 26208 bytes (6552 words = 21 × 312 words).
  The 8th word of each particle is added as the weight.

11.4 Output format reference

  See section 7 of corsika_usage_summary.txt or the comments at code lines 649-1156.

12. Runtime Options and Path Selection
================================================================================

12.1 Conditional branch paths, using CURVED as an example

  (A) Coordinate initialization
      #if __CURVED__
        COOINC (line 9445): spherical-geometry coordinates
      #else
        COORIN (line 10143): planar coordinates
      #endif

  (B) Particle propagation
      #if __CURVED__
        NRANGC / PRANGC: curved-tracking stepping
        THICKC: curved slant depth
      #else
        PRANGE: planar tracking
        BOX2:  determine interaction position in the plane
      #endif

  (C) Electromagnetic processing
      #if __CURVED__
        NKG automatically disabled (FNKG internally forced to F)
      #else
        NKG available (computed at event end)
      #endif

  (D) Output corrections
      #if __CURVED__
        CORRXY correction (in OUTPT1)
        CURVOUT determines the observation-level curvature
      #endif

12.2 Other key option paths

  THIN: add weight computation before TSTEND and in FSTACKO
  UPWARD: modify coordinate signs, allow pz<0 and θ>90°
  SLANT: use slant depth instead of vertical depth in the longitudinal distribution
  PRESHOWER: simulate preshower for γ before entering the atmosphere
  CONEX: replace low-energy particle tracking with cascade equations

13. Extension Point Guide
================================================================================

The following are the key locations to watch when modifying or extending CORSIKA:

13.1 New atmosphere model

  • Add new AATM0/BATM0/CATM0 columns in corsika.h
  • Add coefficients to the DATA statements of BLOCK1 (line 6321)
  • Validate the handling in the THICK/HEIGH functions (line ~17900)
  • Update the ATMOD model list in DATAC

13.2 Modifying the particle output format

  • Add a new keyword in DATAC
  • Modify the output logic of OUTPT1/OUTPT3
  • Update the write format of FSTACKO
  • Update the output-format comments in corsika.h

13.3 Adding a new physics process

  • Decay/interaction of a new particle → add at NUCINT or a suitable dispatch point
  • Stack operations → use STACKINT (intermediate stack) to hold secondary particles → TSTEND
  • New process flag → add keyword parsing in DATAC
  • Validate the ECUTS cutoff and particle ID coding

13.4 Adding a new output option

  • Refer to the implementation pattern of AUGERHIST/MUONHIST
  • Hook into FINISHSHOWER or FSTACKO
  • Use conditional compilation #if __MYOPTION__

13.5 Modifying the coordinate system

  • COOINC (CURVED) or COORIN (planar): initial coordinates
  • UPDATE: final coordinate correction
  • CORRXY: spherical projection correction
  • OUTPT1: coordinate processing before output

13.6 Main data array index mapping

  • PRMPAR(0:39)    - primary
  • CURPAR(0:39)    - current
  • SECPAR(0:39)    - secondary (being constructed)
  • OUTPAR(0:39)    - output
  • STACKI(1:41, *) - in stack
  • index 0=particle ID, 1=energy, 5=x, 6=y, 7=px, 8=py, 9=pz, 20=kinetic energy

13.7 Adding new COMMON blocks

  Recommended to append at the end of corsika.h, to avoid breaking existing numbering.
  Use DOUBLE PRECISION to be consistent with the overall precision of the code.
