1. File Organization
================================================================================

The source tree of CORSIKA 7.8010 is unified in the following files:

1.1 Main source files

  src/corsika.F        — main program file (84803 lines), containing:
    • all Fortran code from program entry to the end
    • implementations of all physics processes
    • #if/#else/#endif conditional-compilation directives controlling the various options
    • input-card documentation and output-format documentation embedded as comments

  src/corsika.h         — header file (5362 lines), containing:
    • all COMMON block definitions
    • data dimension constants (MAXLEN, MAXSTK, MAXBUF, etc.)
    • particle array index constants
    • the STACKFINC include block (particle stack dimension definitions)

1.2 External model files (compiled separately and linked)

  src/sibyll2.3e.f         SIBYLL 2.3e hadronic model
  src/sibyll2.3e-star.f    SIBYLL-star variant
  src/qgsjet01d.f          QGSJET01d model
  src/qgsjet-II-04.f       QGSJET-II-04 model
  src/qgsjet-III.f         QGSJET-III model
  src/gheisha_2002d.f      GHEISHA low-energy hadronic model
  src/venus.f              VENUS model
  src/fluka_interface.f    FLUKA interface
  src/elfield.c            C code for the electric-field option

  Individual hadronic model directories (urqmd/, epos/, herwig/, dpmjet/, nexus/, pythia/):
  unpacked and linked at compile time.

1.3 Header and configuration files

  include/config.h.in   →   ./configure → config.h
     Contains all __OPTION__ macro definitions (generated by coconut)

1.4 C runtime support

  src/trapfpe.c         floating-point exception handling

2. Preprocessor Macro System and Options
================================================================================

2.1 How macros are defined

  CORSIKA uses the C preprocessor (#if / #else / #endif) for conditional compilation:
  - Early versions: options passed to the Fortran compiler via -D__OPTION__
  - Modern versions: macros defined via config.h (generated by ./coconut configuration)

  There are about 3750 #if directives in the code, trimming code according to the
  options activated at compile time.

2.2 Option categories

  (A) Geometry and coordinate systems
    Macro            Function
    __CURVED__    curved atmosphere (spherical Earth, supports θ>70°)
    __SLANT__     slant longitudinal distribution (SLANT option)
    __UPWARD__    upward-going particles (θ>90°)
    __INCLINED__  inclined observation plane (COAST interface)
    __VIEWCONE__  view-cone selection

  (B) Hadronic models
    __SIBYLL__    SIBYLL 2.3
    __QGSJET__    QGSJET-II/QGSJET01d
    __EPOS__      EPOS LHC
    __DPMJET__    DPMJETIII
    __NEXUS__     neXus
    __VENUS__     VENUS
    __HDPM__      HDPM (built-in default)
    __FLUKA__     FLUKA (low energy)
    __GHEISHA__   GHEISHA (low energy, built in)
    __URQMD__     UrQMD (low energy)

  (C) Electromagnetic physics
    __CERENKOV__  Cherenkov photons
    __LPM__       LPM effect
    __EFIELD__    electric field

  (D) Data handling
    __THIN__      thinning
    __MULTITHIN__ multiple thinning
    __THINMAX__   maximum-weight thinning
    __COMPACT__   compressed output
    __EHISTORY__  particle history (mother/grandmother particles)
    __MUADDIOUT__ additional muon output
    __MUPROD__    muon production information
    __NEUTRINO__  neutrino tracking

  (E) Detectors
    __AUGERHIST__ Auger histograms
    __AUGERHIT__  Auger hits
    __ICECUBE1__/__ICECUBE2__  IceCube
    __IACT__      Cherenkov telescopes
    __COAST__     COAST interface
    __COASTUSERLIB__  user library

  (F) Special modes
    __CONEX__     hybrid simulation with cascade equations
    __PRESHOWER__ pre-showering
    __NUPRIM__    primary neutrinos
    __STACKIN__   stack input (external secondary particles)
    __PARALLEL__/__PARALLELIB__  MPI parallelism
    __INTTEST__   interaction tests
    __TRAJECT__   source trajectory tracking
    __CHARM__/__TAULEP__  charm / τ leptons
    __RIGIDITY__  geomagnetic cutoff
    __DYNSTACK__  dynamic stack (runtime allocation)
    __ATMEXT__    external atmosphere (MODTRAN)
    __NRREXT__    extended run numbers

2.3 Option combination constraints

  Important mutual-exclusion/dependency relations:
  - CURVED + CONEX: mutually exclusive (CONEX internally uses part of the CURVED code)
  - CURVED + NKG: NKG automatically disabled (spherical geometry not applicable)
  - THIN + THINMAX: THINMAX must be selected on top of THIN
  - SLANT + CONEX: mutually exclusive
  - INCLINED + COAST: required
  - ROOTOUT + COREAS/COASTUSERLIB/INCLINED: mutually exclusive

2.4 The NON_OPT group

  A set of macros (__NON_OPT0__ through __NON_OPT4__) used to encode the "no options"
  mode, enabled in standard modes without CURVED/SLANT/CERENKOV etc. Contains:
  - the THICK function
  - the HEIGH function
  - BOX2 / BOX3
  - PRANGE
  - UPDATE / OUTPT1
  - MUTRAC

3. Overall Program Flow
================================================================================

3.1 Entry points (polymorphic design)

  PROGRAM AAMAIN (line 1337)
    ↓ (sequential calls)
  SUBROUTINE CORSIKAMAIN (line 1382)    ← core main routine
    ↑
  SUBROUTINE CORSIKA (line 1315, only __PARALLELIB__)
    ── library interface callable from MPI, receiving parameters such as LPRIM

  Near the end of the file there is a backup PROGRAM AAMAIN (line 84794), used when
  HAVE_CONFIG_H is undefined.

3.2 Phase division

  CORSIKAMAIN executes in 4 phases:

  ┌─────────────────────────────────────────────────────┐
  │ Phase 1: Initialization (lines 1382-1920)           │
  │   • call DATAC to read all control cards (→ INPRM) │
  │   • open files (FILOPN)                             │
  │   • write run header block (RUNH)                   │
  │   • initialize random numbers (RMMAQD)              │
  │   • set atmosphere model parameters                 │
  │   • print run parameters (~200 lines to .lst)       │
  ├─────────────────────────────────────────────────────┤
  │ Phase 2: Shower loop (lines 1923-3174)              │
  │   DO ISHW = 1, NSHOW                               │
  │     ① ISTACK: clear the particle stack             │
  │     ② sample primary energy/angle/first-interaction point │
  │     ③ BOX2: determine first-interaction position   │
  │     ④ dispatch by particle type (EM/μ/hadron/neutrino) │
  │     ⑤ ENTRY RUNSHOWER: process the cascade         │
  │     ⑥ ENTRY FINISHSHOWER: per-event statistics     │
  │   END DO                                             │
  ├─────────────────────────────────────────────────────┤
  │ Phase 3: End of run (lines 3175-3183)               │
  │   • ENTRY FINISHRUN: run summary                    │
  │   • write RUNE block                                │
  ├─────────────────────────────────────────────────────┤
  │ Phase 4: Cleanup (after CORSIKAMAIN returns)        │
  │   • close files                                     │
  │   • print CPU time statistics                       │
  └─────────────────────────────────────────────────────┘

3.3 Detailed shower-loop flow

  ┌────────────────────────────────────────────────────────────┐
  │ 1. Sample primary particle parameters                      │
  │    • PRMPAR(0): particle type (fixed or random)            │
  │    • PRMPAR(1): total energy (E⁻ᵞ spectrum or fixed)      │
  │    • THETAP: apparent zenith angle (sinθ·cosθ distribution)│
  │    • PHIP: azimuth angle (uniform)                         │
  │    • first-interaction point: FIXHEI/random (exponential)  │
  │    ┌─ CURVED mode ──────────────────────────┐             │
  │    │ • COOINC: compute initial coordinates in spherical geometry │
  │    │   coordinates → detector system, core at (0,0,0)      │
  │    │ • generate secondary energy/momentum/start position   │
  │    └─────────────────────────────────────────┘             │
  │                                                            │
  │ 2. Dispatch by particle type (lines 3017-3109)             │
  │    γ / e⁺/e⁻ → EM → EGS4 or NKG                           │
  │    μ⁺/μ⁻     → MUPINI → MUTRAC                            │
  │    hadrons    → NUCINT (hadronic interactions)             │
  │    π⁰/K⁰     → decay                                       │
  │    neutrinos  → neutrino tracking                          │
  │                                                            │
  │ 3. Particle stack loop (ENTRY RUNSHOWER, line 3188)        │
  │    DO WHILE (stack not empty)                              │
  │      CALL FSTACK → CURPAR(0:39)                            │
  │      dispatch by CURPAR particle type:                     │
  │      - hadron: CALL NUCINT → produce secondaries → TSTEND → push to stack │
  │      - μ: CALL MUTRAC → propagation/decay/interaction      │
  │      - EM: CALL BOX2 → EGS4                                │
  │      - reached observation level: CALL UPDATE → OUTPT1     │
  │    END DO                                                  │
  │                                                            │
  │ 4. End of event (ENTRY FINISHSHOWER, line 3899)            │
  │    • event statistics                                      │
  │    • NKG lateral distribution (if enabled)                 │
  │    • write EVTE block                                      │
  └────────────────────────────────────────────────────────────┘

4.1 Particle parameter array (0:39 index convention)

  CURPAR/PRMPAR/SECPAR/OUTPAR all use the following indices:

  Index    Meaning
  ─────────────────────────────────────────────
  0       particle ID (particle code, e.g. 14=proton, 5=μ⁺)
  1       total energy (GeV, including rest mass)
  2       zenith angle θ (rad), observation or propagation direction
  3       azimuth angle φ (rad)
  4       particle mass (unused in CURPAR)
  5       x lateral coordinate (cm)
  6       y lateral coordinate (cm)
  7       px, x momentum component (GeV/c)
  8       py, y momentum component (GeV/c)
  9       pz, z momentum component (GeV/c, positive downward)
  10      time of flight (s)
  11-19    (reserved)
  20      kinetic energy (GeV)
  21      total energy recorded again
  22      particle number
  23      observation-level number
  24      hadron generation
  25      (reserved)
  26      particle weight (THIN mode)
  27-39   (option-specific)

5. Particle Stack System (Stack)
================================================================================

The particle stack is CORSIKA's core work queue, using a last-in-first-out (LIFO)
strategy.

5.1 Data structure

  STACKI(0:MAXLEN, 0:MAXSTK)  — main stack
  Each particle occupies MAXLEN+1 = 42 real words (1 word used for internal counting).
  STACKI(0, k) is unused; STACKI(1:41, k) corresponds to CURPAR(0:39) + flag bits.

5.2 Stack operations

  ISTACK (line 20068):
     initializes the main stack: sets MSTACKP to 0, clears counters.

  FSTACK (line 17161):
     pops a particle from the stack:
       MSTACKP = MSTACKP - MAXLEN - 1
       CURPAR(J) = STACKI(MSTACKP+J+1, 0)
     If the stack is empty (MSTACKP ≤ 0), tries to read from disk (NOUREC).
     If there is no more data on disk, IRET1 = 1 signals an empty stack.

  Pushing particles (inline, not a separate subroutine):
     SECPAR is built in processes such as NUCINT/DECAY, then:
       MSTACKP = MSTACKP + MAXLEN + 1
       STACKI(MSTACKP+J+1, 0) = SECPAR(J)
     When the stack is full, it is written to a direct-access disk file (unit LSTCK).

  TSTEND (line 35782):
     transfers STACKINT (the intermediate stack of one nuclear reaction) to the main
     stack STACKI. THIN thinning is applied here (if enabled).

5.3 Stack overflow handling

  When MSTACKP >= MAXSTK * (MAXLEN+1):
    • the current stack contents are written to a direct-access file (LSTCK)
    • MSTACKP is reset to 0
    • NOUREC records the number of blocks written
  Reading back reverses the operation.

5.4 Secondary stack (parallel mode)

  STACKJ — a second stack, used for external particle input (STACKIN) in
  __PARALLEL__ mode or with __COASTUSERLIB__.

  JSTACK (line 20116): initializes the secondary stack
  FSTACKJO (line 17599): pushes onto the secondary stack

6. Control-Card Reading and Parameter Initialization
================================================================================

6.1 Subroutine DATAC (line 10812)

  Reads all input control cards and sets global variables:
  • reads line by line from unit MONIIN (default 5, standard input)
  • recognizes keywords (first 6 characters) and jumps to the corresponding handler
  • handles basic types: I (integer), F (float), L (logical), A (character)
  • case-insensitive (except special character parameters such as EPOPAR/NEXPAR/DIRECT)
  • comment lines: first character c/C + space, or *

6.2 Subroutine INPRM (line 18124)

  After DATAC has read all cards, INPRM performs:
  • reads primary flux weights from the PAPINI file (for spectrum sampling)
  • validates default values
  • computes derived parameters (e.g. atmospheric THICKL)
  • initializes physical constants (C() array)

6.3 Internal handling paths for common cards

  Card           DATAC handling
  ──────────────────────────────────
  RUNNR          → NRRUN (integer)
  EVTNR          → ISHOWNO start
  SEED           → ISEED(3, k) setup
  NSHOW          → NSHOW
  PRMPAR         → PRMPAR(0)
  ERANGE         → LLIMIT, ULIMIT
  ESLOPE         → PSLOPE
  THETAP         → THETPR(1:2) (degrees→radians conversion)
  PHIP           → PHIPR(1:2)
  OBSLEV         → OBSLEV(1:NOSBLV)
  ECUTS          → ELCUT(1:4)
  SIBYLL/SIBSIG  → FSIBYL/FSIBSG flags
  ELMFLG         → FNKG/FEGS
  THIN           → EFRCTHN/WMAX/RMAX
  CURVOUT        → FCURVOUT
  MAGNET         → BX/BZ
  ATMOD          → MODATM
  EXIT           → end of reading

7. Atmosphere Model Subsystem
================================================================================

See atmosphere_model_summary.txt for details (a standalone document in this directory).

7.1 Core functions

  THICK(H)  (line ~17913, __NON_OPT__ group):
     Input:  height H (cm)
     Output: vertical atmospheric depth (g/cm²)
     Formula:
       Layers 1-4: t(h) = A(i) + B(i) * exp(-h / C(i))
       Layer 5:    t(h) = A(5) - h / C(5)

  HEIGH(T)  (line 17906):
     Input:  vertical atmospheric depth (g/cm²)
     Output: height H (cm)
     Inverse of THICK, solved analytically per layer.

  THICKC(OBSLEV, COSIN)  (line ~34128, __CURVED__ group):
     Input:  observation height, cosine of the local zenith angle
     Output: curved slant depth (g/cm²)
     Iteratively solves the slant depth in a spherical atmosphere, using the
     sliding-plane approximation.

7.2 Atmosphere model data

  42 built-in models (MODATM=0~41):
  - MODATM=1: US standard atmosphere (Linsley) [default]
  - MODATM=2~8: central-European atmospheres by month
  - MODATM=11~16: Antarctic (MSIS-90-E)
  - MODATM=17: US standard atmosphere (Keilhauer)
  - MODATM=18~29: Malargüe (Auger, by month)
  - MODATM=30~41: Antarctic IceTop, by month
  - MODATM=0/10: user-defined (ATMA/B/C/ATMLAY)

  5 layer boundaries (HLAY): 4, 10, 40, 100 km, Earth's radius (1e7 cm ≈ geocenter)
  Top layer linear approximation: layer 5 extends to the geocenter.
  Sea-level depth: ~1036 g/cm² (US Standard)

7.3 Key atmosphere-related subroutines

  RFILEATM (line 30092): reads an external atmosphere profile from the ATMFILE file
  ATABSO (line 76338): atmospheric absorption (Cherenkov option)
  External atmosphere A(i)/B(i)/C(i) → internal ATMA/ATMB/ATMC arrays

7.4 Curved atmosphere (CURVED) details

  See curved_option_analysis.txt for details (a standalone document in this directory).

8. Coordinate Systems
================================================================================

8.1 Standard Cartesian system

  Origin: sea level (OBSLEV=0) or the first observation level
  x axis: magnetic north
  y axis: west
  z axis: vertically upward
  Zenith angle θ: relative to the -z axis (straight downward is 0°)
  Azimuth angle φ: counterclockwise from magnetic north (along +x is 0°, +y is 90°)
  Momentum pz: positive downward (convention along the particle propagation direction)

8.2 CURVED-mode sliding plane

  In __CURVED__, Earth's radius C(1)=637131500 cm:
  - particles are continuously tracked in the curved atmosphere
  - the coordinate-system origin is at the detector position at sea level
  - after each step, the local coordinate system is rotated so the z axis points
    again toward the geocenter
  - COOINC (line 9445): computes the apparent-angle → local-angle transformation
  - THICKC (line ~34128): curved-atmosphere slant-depth iteration
  - NRANGC (line 25305): curved tracking of neutral particles
  - PRANGC (line 28849): curved tracking of charged particles (including magnetic field)
  - CORRXY: spherical→plane projection correction (called in OUTPT1)
  - output coordinates OUTPAR(5,6): relative to the detector (horizontal-plane projection)

8.3 INCLINED observation plane

  - an alternative choice independent of CURVED mode
  - defines an inclined plane perpendicular to or containing the shower axis
  - output is in the inclined-plane coordinate system, with (X=0,Y=0) at the
    intersection of the shower axis and the plane

9. Main Loop and Particle Dispatch
================================================================================

9.1 Particle classification and dispatch (lines 3017-3109)

  In the shower loop, after the primary's first interaction the particles enter the
  particle stack; the RUNSHOWER entry (line 3188) starts the main processing loop.
  Per-particle classification and dispatch happen in lines 3320-3860:

  ┌─ dispatch by CURPAR(0) particle type ───────────────────────┐
  │                                                     │
  │  γ, e⁺, e⁻ ──────────→ EM handling                  │
  │    • EGS4: EM subroutine → exact simulation of e/γ cascades │
  │    • NKG (non-CURVED mode): analytic formula        │
  │    └─→ secondaries pushed onto the stack            │
  │                                                     │
  │  μ⁺, μ⁻ ────────────→ MUTRAC subroutine             │
  │    • ionization loss (CDEDXM)                       │
  │    • multiple scattering (Molière/Gauss)            │
  │    • bremsstrahlung / pair production / nuclear interactions │
  │    • decay (MUDECY)                                  │
  │    • propagation to observation level or until energy exhausted │
  │    └─→ arrivals → UPDATE → FSTACKO output           │
  │                                                     │
  │  hadrons ──────────────→ NUCINT subroutine          │
  │    • select high-energy/low-energy model            │
  │    • nuclear interaction → secondaries              │
  │    • unstable-hadron decays (KDECAY, PI0DEC, etc.)  │
  │    └─→ secondaries pushed onto intermediate stack → TSTEND → main stack │
  │                                                     │
  │  neutrinos/τ ─────────→ neutrino/τ propagation      │
  │                                                     │
  │  π⁰ → PI0DEC → γe cascade                           │
  │  K⁰S/K⁰L → KDECAY                                   │
  │  nuclear fragments → fragmentation (NFRAGM)         │
  │                                                     │
  └─────────────────────────────────────────────────────┘

9.2 Stack loop termination conditions

  The stack loop continues until any of the following is met:
  • FSTACK returns IRET1=1 (stack empty and no more on disk)
  • particle count exceeds MAXPRT and time exceeds expectations
  • the maximum stack-depth limit is reached

10. Physics Process Implementations
================================================================================

10.1 Hadronic interactions

  NUCINT (line 25469) — unified entry:
    dispatches by particle type and energy:

    High-energy region (Elab > HILOW, default 80 GeV):
      handled by the model selected at compile time:
        #if __QGSJET__  → QGSLNK (line 69882)
        #if __SIBYLL__  → SIBLNK (line 71686)
        #if __EPOS__    → EPOLNK (EPOS directory)
        #if __DPMJET__  → DPMJLK (line 59542)
        #if __VENUS__   → VENLNK (line 74810)
        #if __NEXUS__   → NEXLNK (line 66418)
        #else           → HDPM   (line 61815, built in)

    Low-energy region (Elab ≤ HILOW):
      #if __FLUKA__     → FLUSTR (line ~54200, FLUKA interface)
      #if __URQMD__     → URQMD (line 68371)
      #else             → GHEISHA (built in)

    Nuclear fragmentation (NFRAGM):
      #if __SIBYLL__/__QGSJET__: the models provide their own fragmentation
      #else: HDPM fragmentation model

    After each interaction:
      secondaries are filled into STACKINT, then TSTEND transfers them to the main stack.

10.2 Electromagnetic interactions

  NKG (non-CURVED mode, lines ~3900-4860 within FINISHSHOWER):
     uses the Greisen approximation formulas for the e⁺/e⁻ lateral and longitudinal
     distributions. Computed at the end of the event; no particles are pushed to the stack.

  EGS4 (line 15590, EM subroutine):
     full simulation of e⁺/e⁻/γ electromagnetic cascades:
     • bremsstrahlung
     • pair production
     • Compton scattering
     • photoelectric effect
     • Møller scattering (Bhabha/Møller)
     Secondaries are managed through EGS4's internal stack.
     Step size controlled by STEPFC.

10.3 Muon physics

  All implemented inside corsika.F (no external libraries):

  MUPINI (line 23859):
     muon-pair initialization (photoproduction γ → μ⁺μ⁻)

  MUPRPR (line 24230):
     preparation of muon propagation parameters

  MUTRAC (line 24621):
     core muon propagation routine:
     • ionization loss: dE/dX (CDEDXM)
     • multiple scattering: (MUMULT selects Molière/Gauss)
     • bremsstrahlung: MUBREM (line 22567), DBRELM (line 12951)
     • pair production: CPRSGM (line 10515)
     • nuclear interactions: MUNUCL (line 23329), CNUSGM (line 9280)
     • decay: MUDECY (line 22938)
     • Coulomb scattering: MUCOUL (line 22874)
     Reaching the observation level → UPDATE (compensated transport to the exact
     observation level)

  UPDATE (lines ~17850-17900, NON_OPT group):
     transports the particle from its current position to the exact observation level:
       OUTPAR(5) = X + SN1 * U10 + ...
       OUTPAR(6) = Y + SN1 * V10 + ...
     • SN1 = (OBSLEV(1) - Z) / CZ (projection along the particle direction)
     • energy-loss correction (dE/dX)
     • CURVED mode: compensated using the sliding plane

10.4 Decays

  DECAY1 (line 13095):
     two-body decays (π⁺→μ⁺ν, K⁺→μ⁺ν, etc.)
     isotropic in the mother's rest frame → transformation to the lab frame

  DECAY2 (line 13345):
     multi-body decays (K⁺→π⁺π⁰, etc.)
     uses phase-space weighting

  DECAY6 (line 13560):
     six-body decays (τ-related)

11. Output System (DAT files)
================================================================================

11.1 File structure

  Fortran unformatted sequential file, default block length 22932 bytes (5733 words × 4 bytes):
  each block = 21 sub-blocks × 273 words.

  ┌─────────┬──────────┬──────────┬──────┬──────────┬─────────┐
  │ RUNH    │ EVTH #1  │ DATA ... │ ...  │ EVTE #1  │ EVTH #2 │
  │ (run header) │ (event header 1) │ particle data blocks │      │ (event trailer 1) │ (event header 2)│
  └─────────┴──────────┴──────────┴──────┴──────────┴─────────┘
  ┌─────────┐
  │ RUNE    │
  │ (run trailer) │
  └─────────┘

  Each write packs the float array into 4-byte words via the C routine tobuf.c
  (line 84440+).

11.2 Key output subroutines

  FSTACKO (line 17544):
     writes particles reaching the observation level (OUTPAR) into the particle-data
     sub-blocks of the DAT file.

  OUTPT1 (line 26485):
     pre-output processing:
     • CURVED mode: calls CORRXY to correct the spherical projection
     • non-CURVED mode: subtracts the XOFF/YOFF core offset

  OUTEND (line 26311):
     writes the EVTE (event trailer) sub-block at the end of an event, including the
     NKG lateral distribution.

  OUTPT3 (line 27447):
     outputs additional muon information (mother particles).

11.3 Output with thinning

  With THIN enabled, the block length grows to 26208 bytes (6552 words = 21 × 312 words).
  Each particle gains an 8th word holding its weight.

11.4 Output format reference

  See section 7 of corsika_usage_summary.txt or the comments at lines 649-1156 of the code.

12. Runtime Options and Path Selection
================================================================================

12.1 Conditional branch paths, using CURVED as an example

  (A) Coordinate initialization
      #if __CURVED__
        COOINC (line 9445): spherical-geometry coordinates
      #else
        COORIN (line 10143): planar coordinates
      #endif

  (B) Particle propagation
      #if __CURVED__
        NRANGC / PRANGC: curved tracking steps
        THICKC: curved slant depth
      #else
        PRANGE: planar tracking
        BOX2:  determine interaction position in the plane
      #endif

  (C) Electromagnetic handling
      #if __CURVED__
        NKG automatically disabled (FNKG forced to F internally)
      #else
        NKG available (computed at end of event)
      #endif

  (D) Output correction
      #if __CURVED__
        CORRXY correction (within OUTPT1)
        CURVOUT decides the observation-level curvature
      #endif

12.2 Other key option paths

  THIN: weight computation added before TSTEND and in FSTACKO
  UPWARD: modifies coordinate signs, allowing pz<0 and θ>90°
  SLANT: longitudinal distribution uses slant depth instead of vertical depth
  PRESHOWER: pre-showering of γ simulated before atmospheric entry
  CONEX: cascade equations replace low-energy particle tracking

13. Extension Point Guide
================================================================================

The following are key locations to focus on when modifying or extending CORSIKA:

13.1 New atmosphere models

  • add new AATM0/BATM0/CATM0 columns in corsika.h
  • add coefficients in the DATA statement of BLOCK1 (line 6321)
  • verify handling in the THICK/HEIGH functions (line ~17900)
  • update the ATMOD model list in DATAC

13.2 Modifying the particle output format

  • add a new keyword in DATAC
  • modify the output logic of OUTPT1/OUTPT3
  • update the write format of FSTACKO
  • modify the output-format comments in corsika.h

13.3 Adding new physics processes

  • decays/interactions of new particles → add at NUCINT or a suitable dispatch point
  • stack operations → use STACKINT (intermediate stack) for secondaries → TSTEND
  • new process flags → add keyword parsing in DATAC
  • verify ECUTS cutoffs and particle ID encoding

13.4 Adding new output options

  • follow the implementation pattern of AUGERHIST/MUONHIST
  • hook into FINISHSHOWER or FSTACKO
  • use conditional compilation #if __MYOPTION__

13.5 Modifying the coordinate system

  • COOINC (CURVED) or COORIN (planar): initial coordinates
  • UPDATE: final coordinate correction
  • CORRXY: spherical projection correction
  • OUTPT1: pre-output coordinate handling

13.6 Main data array index mapping

  • PRMPAR(0:39)    - primary
  • CURPAR(0:39)    - current
  • SECPAR(0:39)    - secondary (under construction)
  • OUTPAR(0:39)    - output
  • STACKI(1:41, *) - on the stack
  • indices: 0=particle ID, 1=energy, 5=x, 6=y, 7=px, 8=py, 9=pz, 20=kinetic energy

13.7 Adding new COMMON blocks

  Recommended to append at the end of corsika.h to avoid breaking existing numbering.
  Use DOUBLE PRECISION to match the overall code precision.
